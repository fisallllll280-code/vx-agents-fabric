# MiroFish ideas and Zapier handoffs under VX

This change extends the repository's existing tool hub, versioned agent registry
and VX tool-control gate. It creates no ChatGPT plugin and no additional sovereign
system. It does not vendor MiroFish or install an upstream runtime dependency.

## Source comparison

Inspected MiroFish source: https://github.com/666ghj/MiroFish at
`7657031ac01184afe2cb220f5ee3545573b5e843` (read-only).
README describes source seeds, graph construction, agent personas, temporal
memory, parallel simulations and reporting. Its LICENSE declares AGPL-3.0.
`backend/app/api/simulation.py` and `backend/app/__init__.py` expose separate
create, prepare, start, stop and run-status routes. Requirements include model,
Zep and OASIS dependencies. Source inspection is not proof of a running endpoint.

| External idea | Existing VX component | Added implementation | Remaining gap |
|---|---|---|---|
| Reality seeds and provenance | Artifact hashes and lineage | Source-linked actor and intervention records | Source bytes/digests must still be independently checked |
| Multiple actor perspectives | Versioned agent registry | VX-SIM-PLAN role and actor input contract | No generated persona/model instance runs |
| Compare alternate worlds | Bounded tool hub | Deterministic baseline and intervention plan compiler | No MiroFish simulation or forecasting executed |
| Temporal memory | Existing ledger/archive | Reset-memory and same-seed experiment controls in plan | Actual temporal memory integration remains NOT_CONFIGURED |
| Simulation report | Proof/governance boundary | Explicit report obligations and NOT_RUN/HOLD labels | Independent empirical validation required |
| Automation delivery | VX action-time tool control | VX-AUTO-ZAPIER and pending action-intent compiler | Authenticated Zapier MCP and action receipt not connected |

Source roots are declared provenance, not automatically independent evidence.
Summaries of the same root stay grouped. Identical content under distinct roots
is rejected. No simulation outcomes, accuracy scores or independent evidence are
fabricated. Tool COMPLETED means the **compiler** ran; nested simulation and
external action execution remain false/NOT_RUN.

## Tools and agents

- `simulation.plan_scenarios` → `VX-SIM-PLAN`, capability `scenario_planning`.
- `automation.plan_zapier` → `VX-AUTO-ZAPIER`, capability `automation_planning`.
- Both roles default to DESIGN_ONLY. The registered-agent dispatcher refuses
  tool access until a trusted host supplies actual admission. Tests use explicit
  synthetic admitted fixtures; no production admission is granted.
- Both tools are pure local planning transformations. They do not accept API
  keys, arbitrary executable code, payload transfers or execution flags.
- All normal specialist calls go through the existing bound dispatcher and its
  allowlists, family/scope checks, budgets and hash-linked receipts.

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

`docs/examples/mirofish-zapier-plan.example.json` is generated by the actual

## Zapier boundary

Official source: https://github.com/zapier/zapier-mcp and
https://help.zapier.com/hc/en-us/articles/48308034391821-What-is-Zapier-MCP
identify the hosted MCP endpoint and app-action model. The authenticated server
is external to that distribution repository. Do not invent credentials or treat
an endpoint URL as an account connection.

The local handoff pins a simulation-plan digest, action request, artifact
references and a stable idempotency key. The hash is a deduplication contract;
it does not implement durable exactly-once delivery. There is no network sender.
The target app/action is an unverified request, not an authenticated catalog ID.
Before execution require authenticated account identity, a fixed tool allowlist,
artifact/data-scope checks, independent action approval, quota/spend authority,
durable idempotency and a result receipt. Sending messages, publication, payment,
trading and deployment never follow implicitly from a simulation output.

## Admission and recovery

Keep production HOLD. Future live MiroFish use requires separate authenticated
transport, cancellation, timeout/retry tests, license review appropriate to the
actual integration, explicit cost authority and independent result verification.
No upstream source code has been copied; this is an independently written local
planning interface inspired by published workflow ideas.

Rollback by reverting the feature commit. Existing agent versions, data and
ledgers are preserved. No production resources are provisioned or changed.
